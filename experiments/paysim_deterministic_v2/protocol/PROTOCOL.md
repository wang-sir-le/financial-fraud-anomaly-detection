# PaySim 确定性版本 v2：运行前约束

机器可读协议 `protocol_effective.json` 在新预测生成前冻结，SHA-256 为 `60f7b18c68a6ffe1b762f2ca721729773c167e75a9b9aefd45343077e298b649`。

1. 旧稿、旧预测、旧统计和旧扩展交付物保持原样，24 个受保护文件的校验值已记录。v2 单独输出，不按结果有利与否决定是否采用。
2. 对指定 SHA-256 的原始 CSV 按数据记录顺序赋予从 0 开始的 source_row_id；保留重复交易的不同源身份。模型不使用身份列。处理顺序固定为 (step, source_row_id)，容量排名的同分决胜采用源身份升序。
3. 金额按分读为整数；历史窗口严格排除同时间戳交易。计数、金额和、平方和在 128 位整数中计算，最后一次转换为浮点均值和样本标准差。先检查全局溢出上界。此变更保持历史窗口和统计量定义，改变数值实现。
4. 全量特征分别以单线程/正向扫描/1 MiB 读取块和 16 线程/逆向扫描/4 MiB 读取块重建，全部类型化字段必须逐值相同；另报序列化文件是否一致。
5. 保持三折时间边界、五个随机种子、模型超参数、特征列顺序和两段验证集不变。覆盖 P0、PT、PH、PTH、PTHW 及原文权重 5 分支，共 90 个 LightGBM 模型；每个重新校准 Platt，P0/PTHW 额外重算 30 个 Isotonic。随后在普通 wheel 的独立环境中对全部 90 个模型进行第二次重建。
6. 测试数据不参与训练、校准和阈值选择；负结果不触发改参数或挑模型。完整报告 660 个容量/成本情景，三阶段组件、100 个共同同分优先级、5,000 次时间块区间及原有块长敏感性。
7. v1 的 processed row_id 与 v2 的 source_row_id 不是同一身份。新旧配对使用同一测试时间组和重采样块；不臆造逐行对应。新旧差异属于处理顺序、精确聚合和同分身份规则的联合实现敏感性，不能作单因素因果解释。
8. 所有区间均条件于已训练模型和既定时间窗，五个种子先在每个重复内平均；区间为逐项区间，不是训练不确定性、同步区间或独立外部验证。
9. 完整差异审查后才决定 C。无论是否启动，LightGBM 结果本身不能证明跨模型成立。摘要、贡献、讨论和受影响数值必须使用相容的证据版本。
10. 取得原始输入的可执行入口和依赖锁随新包交付；本地独立环境通过不等同于外部读者完成复现，也不等同于期刊录用说服力。
